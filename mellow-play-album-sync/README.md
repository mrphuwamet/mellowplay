# mellow-play-album-sync

วางรูปในโฟลเดอร์ แล้วรูปขึ้นในอัลบั้มของ Mellow Play เอง ไม่ต้องเข้า CRM ไม่ต้องลากรูปทีละไฟล์

ทำงานบนคอมของเจ้าหน้าที่เอง ไม่ใช่บนเซิร์ฟเวอร์ — เป็นโปรแกรมเล็ก ๆ ที่**เฝ้าดูโฟลเดอร์**บนเครื่อง แล้วส่งรูปขึ้นผ่าน API ตัวเดียวกับที่ CRM ใช้

## สิ่งที่ต้องมีก่อน

1. **Node.js** — ถ้ายังไม่มี โหลดที่ https://nodejs.org (เลือกเวอร์ชัน LTS)
2. **บัญชีแอดมิน CRM** ของจริง (อีเมล + รหัสผ่าน) — ใช้บัญชีเดิมที่ล็อกอิน CRM

## ติดตั้งครั้งแรก

1. เปิดโฟลเดอร์นี้
2. คัดลอกไฟล์ `.env.example` แล้วเปลี่ยนชื่อเป็น `.env`
3. เปิด `.env` ด้วย Notepad แล้วกรอก:
   - `ADMIN_EMAIL` / `ADMIN_PASSWORD` — บัญชีแอดมินของคุณ
   - `ALBUM_SYNC_ROOT` — ที่อยู่โฟลเดอร์ที่จะใช้วางรูป (ปล่อยว่างไว้ได้ จะใช้โฟลเดอร์ `photos` ข้างในนี้)
4. ดับเบิลคลิก `start.bat` (ครั้งแรกจะติดตั้งของที่จำเป็นให้อัตโนมัติ ใช้เวลาสักครู่)

ถ้าอยากเช็กแค่ว่าอีเมล/รหัสผ่านถูกไหมโดยไม่ต้องเริ่มเฝ้าดูจริง ใช้ `npm run login-check`

## วิธีใช้งาน

**อัลบั้มต้องมีอยู่ใน CRM อยู่แล้ว** — เครื่องมือนี้ใส่รูปเข้าอัลบั้มที่มีอยู่เท่านั้น ไม่สร้างอัลบั้มใหม่ให้

1. ในโฟลเดอร์ที่ตั้งไว้ (`ALBUM_SYNC_ROOT`) สร้างโฟลเดอร์ย่อยชื่อ**ตรงกับชื่ออัลบั้มใน CRM เป๊ะ ๆ** เช่น ถ้าอัลบั้มชื่อ "งานกีฬาสี 2569" ก็สร้างโฟลเดอร์ชื่อ "งานกีฬาสี 2569"
2. ข้างในโฟลเดอร์นั้น จะมี (หรือโปรแกรมจะสร้างให้เมื่อรูปแรกถูกประมวลผล):
   ```
   งานกีฬาสี 2569/
     New/        <- วางรูปที่นี่
     Uploaded/   <- โปรแกรมย้ายรูปมาที่นี่เมื่ออัปโหลดสำเร็จ
     Failed/     <- ถ้าอัปโหลดไม่สำเร็จ รูปจะมาอยู่ที่นี่ พร้อมไฟล์ .error.txt บอกเหตุผล
   ```
3. วางรูป (ลาก-วาง หรือก็อปปี้) ลงใน `New/` — โปรแกรมเห็นปุ๊บ อัปโหลดให้ทันที ไม่ต้องรอ ไม่ต้องกดอะไร
4. รูปจะไปโผล่ในอัลบั้มนั้นที่ CRM และหน้าเว็บทันทีที่อัปโหลดเสร็จ

สามารถมีหลายอัลบั้มพร้อมกันได้ — สร้างหลายโฟลเดอร์ย่อย แต่ละอันอัลบั้มของตัวเอง

**ปล่อยโปรแกรมนี้รันค้างไว้ได้เลย** (หน้าต่างสีดำที่เปิดขึ้นมา อย่าปิด) จะเฝ้าดูตลอดจนกว่าจะปิดหน้าต่าง

## สิ่งที่โปรแกรมทำให้อัตโนมัติ

- ย่อรูปเป็น 2 ขนาด (รูปเต็มกับรูปย่อ) เหมือนที่ CRM ทำตอนซิงค์จาก Google Drive — คุณภาพและขนาดไฟล์เท่ากัน
- หมุนรูปให้ถูกทิศ (บางรูปจากมือถือมีปัญหาแนวนอน/แนวตั้งสลับ)
- ถ้ารูปเดิมถูกวางซ้ำ (เผลอก๊อปปี้ไฟล์เดิมสองรอบ) จะไม่อัปโหลดซ้ำให้
- ถ้าอินเทอร์เน็ตหลุดระหว่างอัปโหลด จะลองใหม่ให้อัตโนมัติ 3 รอบก่อนจะย้ายไป Failed/
- ล็อกอินใหม่ให้เองทุก 12 ชั่วโมง (กันเซสชันหมดอายุตอนปล่อยรันข้ามคืน)

## สิ่งที่โปรแกรมนี้ "ไม่" ทำ (ทำช่องทางอื่นแทน)

- **ไม่ทำดัชนีใบหน้าให้** — การค้นหาใบหน้าต้องใช้ตัวตรวจจับที่หนักและรันในเบราว์เซอร์เท่านั้น (เหมือนตอนซิงค์จาก Drive) หลังอัปโหลดเสร็จ เข้า CRM แล้วกดปุ่ม **"สร้างดัชนีใบหน้า"** ที่หน้าอัลบั้มนั้น ๆ ได้เลย ปุ่มนี้ทำเฉพาะรูปที่ยังไม่มีดัชนีอยู่แล้ว
- **ไม่สร้างอัลบั้มใหม่ให้** — สร้างอัลบั้มที่ CRM ก่อนเสมอ (ตั้งชื่อ ผูกคลาส ตั้งค่าการมองเห็น) แล้วค่อยสร้างโฟลเดอร์ชื่อเดียวกันมาวางรูป

## เรื่องความปลอดภัย

- ไฟล์ `.env` มีรหัสผ่านแอดมินอยู่ข้างใน **ห้าม commit เข้า git และห้ามส่งไฟล์นี้ให้ใครต่อ** (มี `.gitignore` กันไว้ให้แล้ว แต่ก็อย่าเอาไปแชร์เองอยู่ดี)
- โปรแกรมจะอัปโหลดอะไรไม่ได้เลยถ้าล็อกอินไม่ผ่าน — เซิร์ฟเวอร์ปฏิเสธทุก request ที่ไม่มี token ของแอดมินจริง เหมือนที่ CRM เองก็โดนกฎเดียวกัน
- ถ้าไม่อยากเก็บรหัสผ่านไว้ในไฟล์ `.env` เลย ตั้งค่า `ADMIN_PASSWORD` เป็น environment variable ของเครื่องแทนได้ (ปลอดภัยกว่า เพราะไม่ได้นอนอยู่ในไฟล์ข้อความธรรมดา) — โปรแกรมจะอ่านค่านั้นก่อนเสมอถ้ามี

## เชื่อมกับ LumaBooth (ตู้ถ่ายรูป)

เปิด LumaBooth ถ่ายรูปในงาน แล้วรูปไหลมาเข้าอัลบั้มเองโดยไม่ต้องยุ่งเลย — ใช้ตัวช่วยอีกตัวหนึ่งในชุดนี้ชื่อ `start-lumabooth.bat`

**ทำไมไม่เสียบตรงเข้า LumaBooth's "Post-Processing" ที่เห็นในหน้าตั้งค่า** — ช่องนั้นเรียกโปรแกรมภายนอกแล้ว**รอ**ผลก่อนจะถ่ายรูปต่อไปได้ แต่ไม่มีเอกสารที่ไหนบอกชัดว่าส่ง argument แบบไหนมาให้ ถ้าเดาผิดเสี่ยงบูธค้างกลางงานต่อหน้าแขก จึงเลือกใช้ฟีเจอร์ **"Real-time export"** แทน (Settings → General → Real-time export) ซึ่งเป็นฟีเจอร์ที่มีเอกสารรองรับจริง ทำหน้าที่ "สำเนารูปออกไปที่โฟลเดอร์อื่นทันทีที่ถ่ายเสร็จ" โดยไม่ไปยุ่งกับการทำงานของตัวบูธเลย

### ตั้งค่า

1. **ฝั่ง LumaBooth**: Settings → General → Real-time export → เปิดใช้งาน เลือกสำเนา **Originals** → เลือกปลายทางเป็นโฟลเดอร์ว่าง ๆ สักอัน เช่น `C:\mellow-lumabooth-export`
2. **ฝั่งไฟล์ `.env`**: กรอก
   - `LUMABOOTH_EXPORT_ROOT` = โฟลเดอร์เดียวกับที่ตั้งไว้ในข้อ 1
   - `LUMABOOTH_TARGET_ALBUM` = ชื่ออัลบั้มใน CRM ที่จะรับรูปจากบูธงานนี้ (กติกาเดียวกับโฟลเดอร์อื่น — ต้องมีอัลบั้มนี้อยู่ใน CRM แล้ว)
3. เปิด **ทั้งสองหน้าต่างพร้อมกัน**: `start.bat` (ตัวที่อัปโหลดจริง) และ `start-lumabooth.bat` (ตัวที่รับรูปจาก LumaBooth มาวางที่ `New/`) — ขาดตัวใดตัวหนึ่งรูปจะไม่ไปถึงอัลบั้ม

จากนั้นเปิด LumaBooth ถ่ายได้เลย รูปจะไหลเข้า `New/` ของอัลบั้มที่ตั้งไว้ แล้วเครื่องมือหลักก็อัปโหลดต่อให้เหมือนวางรูปเองทุกอย่าง

**ข้อควรรู้**: รับเฉพาะรูปที่ถ่าย*หลังจาก*เปิด `start-lumabooth.bat` เท่านั้น รูปเก่าที่เคยถ่ายไว้ก่อนหน้าจะไม่ถูกดึงย้อนหลังมาเอง (กันกรณีใช้โฟลเดอร์ export เดิมซ้ำหลายงานแล้วจู่ ๆ ดึงรูปงานเก่ามาปนกัน) ถ้าอยากเอารูปเก่าเข้าด้วย ลากทั้งโฟลเดอร์ไปวางใน `New/` ของอัลบั้มนั้นตรง ๆ ได้เลย

**ทำไมรับแค่โฟลเดอร์ Originals**: LumaBooth สร้าง `<ชื่อ session>/Originals/` กับ `<ชื่อ session>/Prints/` เป็นโฟลเดอร์คู่กันเสมอ — Prints คือรูปเดียวกันแต่ใส่กรอบ/โลโก้งานทับไว้สำหรับพิมพ์ ไม่ใช่รูปคนละใบ ถ้ารับทั้งสองโฟลเดอร์ รูปทุกใบจะเข้าอัลบั้มซ้ำสองรอบ (ใบเปล่ากับใบมีกรอบ) ตัวรีเลย์เลยรับเฉพาะโฟลเดอร์ชื่อ "Originals" เท่านั้นโดยค่าเริ่มต้น ถ้าอยากได้เวอร์ชันมีกรอบในอัลบั้มแทน เปลี่ยน `LUMABOOTH_SUBFOLDER` ใน `.env` เป็น `Prints`

## ถ้าเฝ้าดูโฟลเดอร์บน Network Drive / NAS แล้วรูปไม่ขึ้น

ตั้ง `WATCH_USE_POLLING=true` ใน `.env` — บาง network share ไม่ส่งสัญญาณไฟล์เปลี่ยนแปลงแบบปกติ โหมดนี้จะคอยเช็กเองแทน (กิน CPU นิดหน่อยแต่ทำงานได้แน่นอน)
